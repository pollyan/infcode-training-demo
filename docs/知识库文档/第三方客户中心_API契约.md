# 星辰集团统一客户中心 API 契约协议

## 1. 接口基础信息
- **接口名称**：按客户编号查询企业客户基础档案
- **通信协议**：HTTP / RESTful
- **服务地址**：`GET http://localhost:9090/api/v1/customers/{customerCode}`
- **鉴权要求**：v1 为 2019 年上线的历史遗留接口，早于集团统一鉴权体系，**未纳入应用凭证校验**。2025 年上线的 v2 扩展档案接口起，请求头必须携带身份标识 `X-App-Key: xingchen-crm-local`（缺失该请求头会导致 401 认证失败）。

## 2. 响应报文结构规范
外部客户中心接口的数据结构偏向历史遗留系统的下划线命名风格。所有本系统的集成服务，**禁止将外部报文结构直接透传给前端**，必须做一层内部数据传输对象（DTO）映射的隔离。

### 2.1 成功响应 JSON 示例
```json
{
  "code": "200",
  "message": "success",
  "data": {
    "cust_code": "C202503001",
    "cust_name": "上海星河建设有限公司",
    "cust_status": "ACTIVE",
    "contact_phone": "13800000000",
    "updated_at": "2026-03-22 10:30:00"
  }
}
```

> 注意：`code` 为字符串类型；时间字段格式为 `yyyy-MM-dd HH:mm:ss`；`contact_phone` 可能为 `null`（客户档案处于补录状态），集成方需做空值保护，不得以空串覆盖本地已有数据。

### 2.2 常见错误码 (Error Codes) 对照表
集成方（后端）需要针对不同的业务错误做捕获与统一包装：
- `200`: 请求成功且正常（注：HTTP 200 且信封 code 为 "200" 但 `data` 为 `null` 时，表示该客户档案待修复/数据异常，**必须视为失败处理**，不得静默当作同步成功）。
- `4001`: 参数校验失败（非法格式、应用凭证缺失）。
- `4004`: 客户档案不存在。
- `5000`: 上游核心链路熔断，服务不可用（建议稍后重试）。
- `5002`: 请求触发并发限流 (Rate Limit Exceeded)。

## 3. v2 扩展档案接口（概要）

2025 年客户中心上线第二代查询接口，在基础档案之外提供信用等级、行业分类、联系人列表、开票信息、档案数据版本号等扩展字段：

- **服务地址**：`GET http://localhost:9090/api/v2/customers/{customerCode}/profile`
- **鉴权要求**：请求头携带 `X-App-Key`（要求同上）
- 部分存量客户未开通扩展档案，查询时返回 404 / code 4004

字段级结构、取值域与业务展示语义以客户中心侧最新技术资料为准，本文档不展开。

## 4. 联调环境场景客户

客户中心联调环境内置以下场景客户，集成验收时应覆盖：

| 客户编号 | 场景 |
| --- | --- |
| C202503001 / C202504021 | 正常档案 |
| C202503002 | 正常档案，但 `contact_phone` 为 `null`（验证空值保护） |
| C202503500 | 核心链路熔断（HTTP 500 + code 5000） |
| C202503998 | 档案待修复（HTTP 200 + code "200" + data 为 null） |
