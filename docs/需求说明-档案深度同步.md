# 需求说明：客户档案深度同步与合同系统联动

请基于现有“客户主数据列表页”新增一个真实增量需求。

## 业务背景

当前存在两个业务痛点：

1. 本地 CRM 的客户档案长期滞后于集团客户中心维护的主数据，销售与客户成功团队
   联系不上客户、处理滞后；且本地目前只有名称、状态、电话等基础字段，
   信用等级、所属行业、联系人清单、开票信息等完整档案内容一直缺失。
2. 合同管理系统里维护了一份客户名称与状态的冗余档案，两边各自维护、
   经常不一致，合同侧经常拿着过期的客户名称与状态开票与履约。

## 需求要求

1. 页面保留现有筛选区、统计卡和客户列表
2. 在每条客户记录的操作列新增“同步外部档案”操作，可重复执行（幂等覆盖）
3. 点击后调用后端同步接口，后端从客户中心获取该客户的完整档案，
   包括基础资料与扩展档案（信用等级、所属行业、联系人列表、开票信息）
4. 同步完成后，当前行的基础字段原位刷新（不得整页刷新，保留筛选与翻页上下文），
   并在页面提供查看该客户完整档案的入口
5. 信用等级展示须区分正常评级与信用冻结两类业务语义，不得混同展示
6. 同步成功后，将客户最新名称与状态推送给合同管理系统，更新其冗余档案；
   推送失败不得影响本地同步结果展示，但须给出可观察的失败信息
7. 同步失败时展示友好错误提示（含客户档案不存在、档案数据异常、
   上游服务不可用等场景），不透出底层英文报错与堆栈
8. 外部系统的数据结构与内部展示隔离，禁止将外部报文结构直接透传到前端
9. 联系电话沿用既有安全规范脱敏展示；联系人清单中的电话同样处理
